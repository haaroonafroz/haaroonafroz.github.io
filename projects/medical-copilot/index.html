PERSONAL PROJECT · HEALTHCARE AI · COMPUTER USE

Medical Co-Pilot
A browser agent for a reviewed clinical handoff.

I built a synthetic discharge workflow to explore how a computer-use agent can transfer a clinician-approved packet into a mock hospital form, pause when the destination is unclear, and verify the saved result. The project started as an agentic RAG copilot; this handoff demo is a separate workflow.

See the workflow View code and run guide ↗
STATUSSynthetic proof of concept
SOURCEFHIR patient records
OPERATORDOM + vision · mouse + keyboard
OBSERVABILITYArize Phoenix traces

01 · HANDOFF WORKFLOW

Review the source. Operate the form. Verify the draft.

The model receives approved values and source references, plus a fresh DOM summary and screenshot of the form. It chooses one browser action at a time; Playwright executes that action. A person controls clinical approval and ambiguous choices.

01 · PREPARE

Ground every field.

A deterministic FHIR mapping builds the discharge sheet with links to source records. Missing or conflicting entries need clinician resolution before approval.

02 · OPERATE

Use the browser.

GPT-6 Luna selects DOM or screenshot-informed mouse and keyboard actions. The agent can navigate tabs, fill fields and pause for a person when two destinations seem plausible.

03 · CHECK

Verify persistence.

The app blocks saving until form fields match the approved packet. After Save draft, it reloads the form and checks all 11 persisted fields.

02 · WHAT THE DEMO SHOWS

Inspectable decisions and failure paths.

The scenarios vary the form rather than the clinical packet: a standard form, tabs, a visual-only label, an ambiguous destination and a transient save error.

03 · OBSERVABILITY

Trace the decision, action and result.

Arize Phoenix groups a run by the session ID shown in the demo. Child spans capture the model input, chosen tool and short reason, browser action, errors, token use and verification outcome. The captured content is limited to the synthetic handoff workflow.

SCOPE AND NEXT STEPS

A research prototype, with visible limits.

This runs on synthetic patient data and an invented hospital form. It is not connected to a real HIS, validated for clinical use, or ready for real patient data. The next work is broader form and failure evaluations, durable resumable runs, stronger access and privacy controls, and recovery when interfaces change.
